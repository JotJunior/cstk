# A11Y Checklist: GitHub Pages — Manual do cstk

**Purpose**: Validar a QUALIDADE dos requisitos de acessibilidade —
hierarquia semantica, navegacao por teclado, contraste, foco visivel,
funcionamento sem JavaScript, leitor de tela e atalhos de busca. Items
abaixo testam se os REQUISITOS estao bem-escritos e auditaveis — nao a
implementacao.

**Created**: 2026-05-19
**Feature**: [spec.md](../spec.md)
**Domain**: a11y
**Aderente a**: Constitution-delta D-V (WCAG AA — Accessibility-Floor);
FR-012, FR-013, FR-014; SC-003, SC-010.

---

## 1. Threshold e Mensurabilidade (D-V)

- [ ] CHK001 - O criterio "Lighthouse Accessibility >=90" (FR-012,
  SC-003) define a versao/configuracao do Lighthouse usada para que
  pontuacoes sejam reproduziveis (CI run vs local)? [Mensurabilidade,
  Spec §FR-012]
- [ ] CHK002 - A spec define o que acontece se a pontuacao cai abaixo
  de 90 em uma das duas paginas auditadas (landing OU detail) — falha
  bloqueante de CI ou warning? [Gap, Spec §FR-012, §SC-009]
- [ ] CHK003 - O escopo "uma pagina-detalhe de skill representativa"
  (FR-012/SC-003) define COMO escolher a representativa (skill com
  maior conteudo? aleatoria? especifica)? [Ambiguity, Spec §FR-012]
- [ ] CHK004 - A clausula "em ambos os temas (claro e escuro) se houver
  multiplos temas" (FR-012) tem requisito explicito de que a feature
  DEVE oferecer dark mode, ou esta condicionada a default da stack?
  [Ambiguity, Spec §FR-012, §Assumptions]
- [ ] CHK005 - O criterio "sem violacoes criticas" (Acceptance Scenario
  1 do US 6) tem definicao de "critica" alinhada com criterios WCAG
  AA (axe-core rules de severity 'serious'/'critical')?
  [Clareza, Spec §US6 AS1]
- [ ] CHK006 - SC-003 cobre apenas Lighthouse — existem requisitos
  complementares (axe-core, WAVE, manual screen-reader test) ou
  Lighthouse e a unica gate definida? [Completude, Spec §SC-003]

## 2. Estrutura Semantica (FR-013)

- [ ] CHK007 - O requisito "hierarquia de headings sem pulos" esta
  definido com regra binaria — `h1` unico por pagina, `h2` segue
  apenas `h1`, etc.? [Clareza, Spec §FR-013]
- [ ] CHK008 - A regra de hierarquia cobre paginas geradas a partir
  de `.md` fonte cujo proprio markdown ja tem hierarquia "errada"
  (ex: SKILL.md comecando em `##` em vez de `#`)? [Edge Case, Gap]
- [ ] CHK009 - A definicao de "foco visivel" em FR-013 e objetiva
  (contraste minimo do outline, espessura minima, persistencia em
  todos os controles)? [Clareza, Spec §FR-013]
- [ ] CHK010 - O requisito `<html lang="...">` em FR-013 esta
  consistente com Assumptions ("lang=pt-BR por padrao, overrides
  via frontmatter")? [Consistencia, Spec §FR-013, §Assumptions]
- [ ] CHK011 - Existe requisito sobre alt text para imagens
  referenciadas em paginas (mesmo que seja "honrar alt do markdown
  fonte")? [Gap, Spec §FR-013]
- [ ] CHK012 - Existe requisito sobre semantica de landmarks
  (`<main>`, `<nav>`, `<header>`, `<footer>`) ou esta delegado
  implicitamente ao tema da stack? [Gap, Spec §FR-013]

## 3. Navegacao por Teclado (FR-013, US 6)

- [ ] CHK013 - O requisito "navegavel por teclado com foco visivel"
  cobre a ordem de tabulacao — alinhada com a ordem visual? [Clareza,
  Spec §FR-013, §US6 AS2]
- [ ] CHK014 - O requisito cobre skip-link ("pular para conteudo
  principal") ou esta ausente da spec? [Gap, Spec §FR-013]
- [ ] CHK015 - O criterio de "ordem visual" em US 6 AS2 esta definido
  para layouts responsivos (mobile reordena visualmente — a ordem
  de TAB deve seguir DOM ou viewport visual)? [Ambiguity, Spec §US6
  AS2]
- [ ] CHK016 - O requisito de navegacao por teclado cobre menus
  dropdown / toggle de tema / dark-mode switch (se houver)? [Edge
  Case, Gap]
- [ ] CHK017 - Existe requisito para que NENHUM elemento interativo
  fique inacessivel via TAB (tab-trap, `tabindex="-1"` em controles
  visiveis)? [Gap, Spec §FR-013]

## 4. Funcionamento sem JavaScript (FR-014, SC-010)

- [ ] CHK018 - O conjunto de "funcoes essenciais" que devem funcionar
  sem JS esta enumerado exaustivamente (FR-014 lista: leitura,
  navegacao TOC, links internos) — copy-button, dark-mode, busca
  sao explicitamente "progressive enhancement"? [Completude, Spec
  §FR-014]
- [ ] CHK019 - O criterio de SC-010 ("pelo menos um navegador
  moderno") tem definicao de "moderno" (Firefox/Chrome/Safari
  ultimas 2 versoes)? [Mensurabilidade, Spec §SC-010]
- [ ] CHK020 - O comportamento da busca com JS desabilitado esta
  definido — desaparece silenciosamente, mostra mensagem "requer
  JS", ou ha fallback (ex: link para grep GitHub)? [Gap, Spec
  §FR-014, §FR-006]
- [ ] CHK021 - O TOC (table of contents) tem requisito de gerar
  HTML estatico (anchors `<a href="#section">`) em vez de
  construir via JS no client? [Clareza, Spec §FR-014]
- [ ] CHK022 - Existe requisito de que paginas exibam contraste
  legivel mesmo sem CSS do tema (ex: CSS falha no carregamento) —
  ou esta fora do escopo? [Gap]

## 5. Acessibilidade da Busca (FR-006, US 5)

- [ ] CHK023 - O atalho de teclado para foco no campo de busca
  (US 5 AS2: "/" ou "s") esta consistente com defaults do
  mkdocs-material (que usa "s" e "f" por default)? [Consistencia,
  Spec §US5 AS2, Stack]
- [ ] CHK024 - O requisito "consegue digitar e buscar sem usar o
  mouse" (US 5 AS2) cobre navegacao entre RESULTADOS de busca via
  teclado (Arrow keys + Enter) ou apenas o foco no input?
  [Completude, Spec §US5 AS2]
- [ ] CHK025 - Existe requisito de aria-live region para anunciar
  numero de resultados encontrados a screen-readers? [Gap, Spec
  §US5]
- [ ] CHK026 - O snippet de resultado com "termo destacado" (US 5
  AS1) tem requisito de NAO usar APENAS cor para indicar destaque
  (WCAG 1.4.1 Use of Color)? [Gap, Spec §US5 AS1]
- [ ] CHK027 - Existe requisito sobre o estado "nenhum resultado
  encontrado" — texto descritivo, foco mantido, screen-reader
  anuncia o estado? [Gap, Spec §US5]

## 6. Contraste e Apresentacao Visual

- [ ] CHK028 - Existe requisito explicito de contraste minimo WCAG AA
  (4.5:1 para texto normal, 3:1 para large text) ou esta delegado
  ao "default do tema"? [Gap, Spec §FR-012]
- [ ] CHK029 - Code blocks (alto risco de baixo contraste em temas
  custom) tem requisito de cumprir o mesmo contraste minimo?
  [Edge Case, Gap]
- [ ] CHK030 - O requisito cobre o caso de usuario com
  `prefers-reduced-motion` ativo — animacoes do tema devem
  respeitar essa preferencia? [Gap]
- [ ] CHK031 - Existe requisito de tamanho minimo de texto
  (16px base recomendado para body) ou zoom 200% sem perda de
  conteudo (WCAG 1.4.4)? [Gap]

## 7. Edge Cases e Cobertura

- [ ] CHK032 - O Edge Case "JavaScript desabilitado" esta consistente
  entre FR-014 (geral) e o User Story 5 (busca explicitamente
  requer JS — conflito? ou US5 e P2 condicionado a JS habilitado)?
  [Consistencia, Spec §FR-014, §US5]
- [ ] CHK033 - Para skills com conteudo MUITO LONGO (>1000 linhas),
  existe requisito sobre paginacao ou TOC anchor links para nao
  forcar scroll-fatigue (relevante para usuarios de leitor de
  tela)? [Edge Case, Gap]
- [ ] CHK034 - Existe requisito para PRINT stylesheet (impressao
  da documentacao) — uso legitimo para acessibilidade
  cognitiva? [Gap]
- [ ] CHK035 - Imagens decorativas vs informativas — existe
  requisito de marcar decorativas com `alt=""`? [Gap]

## 8. Consistencia Cross-Requirement

- [ ] CHK036 - O nivel exigido em D-V ("WCAG AA") esta consistente
  com FR-012 (Lighthouse >=90) — Lighthouse score 90 NAO garante
  conformidade WCAG AA total (cobertura parcial); existe gap entre
  requisito constitutional e gate operacional? [Conflict, Spec §D-V,
  §FR-012]
- [ ] CHK037 - SC-003 mensura apenas 2 paginas (landing + 1 detail);
  existe garantia de que as ~43 paginas auto-geradas (SC-006)
  HERDARAO o nivel testado — ou cada detail-page pode ter problema
  unico nao auditado? [Cobertura, Spec §SC-003, §SC-006]
- [ ] CHK038 - O requisito de acessibilidade aplica-se ao
  CHANGELOG.md (Assumptions) e a outras paginas opcionais ou
  apenas a paginas core? [Completude, Spec §Assumptions]
